# Overseas Demand Radar

한국 시장의 해외직구 **수요 신호를 먼저 탐지**하고, 유망한 상품에 한해 해외 공급처
탐색과 구매대행 수익성 비교를 수행하는 상품 발굴 시스템.

> 성공 기준은 상품을 많이 수집하는 것이 아니라, **검토 가치가 있는 상품을 높은
> 정확도로 선별하고 그 판단 근거를 설명**하는 것.

현재 구현 범위: **Phase 1 (분석 엔진) + Phase 2 (수요 데이터 연동) + Phase 3 (해외 공급처 탐색)**.
API 키 없이도 CSV·샘플 데이터만으로 전체 흐름(가져오기 → 키워드 후보 → 수요-상품 연결 →
원가 → 점수 → 근거 → 내보내기)이 동작합니다. NAVER API HUB 키를 설정하면 실제 검색어
트렌드/쇼핑인사이트 수요를, eBay·라쿠텐 키를 설정하면 해외 공급처 가격을 수집합니다. 국내 비교가는 CSV로 가져옵니다.

### 네이버 API HUB 키 발급 (선택)

2026-06-25부터 검색어 트렌드·쇼핑 인사이트는 **NAVER API HUB**(네이버 클라우드 플랫폼)에서 제공되며, 네이버 개발자센터
(developers.naver.com) 키는 사용할 수 없습니다.

1. 네이버 클라우드 플랫폼 콘솔 → All Services → Application Services → **NAVER API HUB** → Application → Application 등록
   (콘솔 직접 링크: https://console.ncloud.com/naver-api-hub/application, NCP 계정 필요)
2. 사용 API에 **검색어 트렌드**, **쇼핑 인사이트**를 선택
3. 해당 Application의 **인증 정보**에서 Client ID/Client Secret을 `.env`의 `NAVER_CLIENT_ID` / `NAVER_CLIENT_SECRET`에 입력.
   Secret이 노출되면 같은 화면에서 재발급.
4. 호출: `https://naverapihub.apigw.ntruss.com`, 헤더 `X-NCP-APIGW-API-KEY-ID` / `X-NCP-APIGW-API-KEY`.
   401은 키 오류이거나 Application에 해당 API가 등록되지 않은 경우, 429는 일 호출 한도 초과입니다.
   무료 한도는 문서에서 확인하지 못했으니 콘솔에서 확인하세요.
5. 쇼핑 인사이트가 검색어 트렌드와 **다른 Application**이면 그 Application의 키를
   `NAVER_SHOPPING_CLIENT_ID` / `NAVER_SHOPPING_CLIENT_SECRET`에 입력 (같은 Application이면 비워 두세요).
6. 쇼핑 인사이트를 쓰려면 `config/naver_categories.yaml`에 카테고리별 쇼핑 분야 코드
   (네이버쇼핑 카테고리 URL의 `cat_id`)를 직접 확인해 입력. 미설정 시 해당 소스는 건너뜁니다.

> **네이버 쇼핑 검색 API는 2026-07-31 종료**되었고 NAVER API HUB를 포함한 대체 API가 없습니다(네이버 공지).
> 그래서 국내 비교가 자동 수집은 제거했습니다. 국내가는 `domestic_offers.csv`로 가져오세요.

### eBay / 라쿠텐 키 (선택)

- **eBay**: https://developer.ebay.com 가입 → Application Keys에서 **Production** 키셋
  (App ID = Client ID, Cert ID = Client Secret)을 `.env`에 입력. Browse API를 client credentials 토큰으로 호출합니다.
- **라쿠텐**: https://webservice.rakuten.co.jp 에서 라쿠텐 계정으로 New App 등록 (앱 이름·URL·유형·허용 웹사이트·
  이용 목적·예상 QPS 입력) → **App ID와 Access Key 둘 다** 입력. 이용약관상 화면에 크레딧
  ("Supported by Rakuten Developers") 표시가 필요하며, 라쿠텐 키나 데이터가 있으면 앱 하단에 자동 표시됩니다.

키가 없으면 네이버 수집은 오류 없이 **건너뜀(skipped)** 으로 기록되고 CSV 분석은 그대로 동작합니다.

## Phase 2 동작 방식

**키워드 후보 생성 (규칙 기반, PRD 9.1/9.2)** — 상품 속성과 사용자 사전으로 구체적인 순서대로
생성: 모델번호 → 브랜드+모델 → 브랜드+상품명 → 한글 브랜드+별칭 → 한글 브랜드+카테고리어.
LLM 출력은 사용하지 않으며, 사전(`brand_aliases.yaml`)은 사용자가 확인한 값만 넣습니다.

**수요-상품 연결 (PRD 9.3)**

| 근거 | 상태 | 신뢰도 |
|---|---|---:|
| GTIN 일치 | 자동 연결 | 1.00 |
| 모델번호 일치 | 자동 연결 | 0.95 |
| 브랜드 + 상품명/별칭 | 자동 연결 | 0.85 |
| 브랜드 + 카테고리어 | 검토 필요 | 0.60 |
| 상품명/별칭만 | 검토 필요 | 0.50 |
| 브랜드만 | 검토 필요 | 0.40 |

- 점수에는 **자동 연결·사용자 확정** 키워드의 수요만 반영됩니다. 검토 필요 연결은 반영되지
  않고 `수요 연결 검토 필요` 위험 요소로 표시됩니다.
- 한 키워드가 식별자 없이 여러 상품에 자동 연결되면 모호한 것으로 보고 검토 필요로 낮춥니다.
- 사용자의 확정/제외 결정은 자동 매칭이 덮어쓰지 않습니다.

**네이버 데이터랩 수집** — NAVER API HUB 공식 문서로 확인한 엔드포인트만 사용합니다
(`POST /search-trend/v1/search`, `POST /shopping/v1/category/keywords`, 호스트 `naverapihub.apigw.ntruss.com`).
- 최근 8주(월~일 완결 주) 주간 데이터를 받아 **최근 4주 vs 직전 4주** 성장률 계산(PRD 7.3).
- 응답 값은 요청 안에서 최댓값=100인 상대값이라, 검색어 트렌드는 모든 요청에 기준 키워드를
  넣고 `수요지수 = 50 + 25 × log10(키워드 최근값 / 기준 키워드 최근값)`(0~100 제한)으로 요청 간 척도를 맞춥니다.
  (기준 키워드와 같으면 50, 10배면 75. 실제 응답에서 상품 키워드가 기준의 10배 이상이라 단순 비율은 모두 100이 되었습니다.)
- 쇼핑인사이트 지수는 요청(최대 5개 키워드) 내 상대값입니다.
- 요청당 그룹 수 제한(5개), 실행당 호출 상한, 요청 간격, 5xx/429 재시도(최대 2회)를 지킵니다.
  401/403은 재시도하지 않고 수집을 중단하며 데이터 소스에 오류를 기록합니다.

**점수 근거** — 모든 기회에 가중치, 입력값, 사용된 수요 신호(출처·기간·지표 유형), 연결 키워드와
근거, 비용 항목별 내역과 가정값, 환율 제공자·기준 시각, 공급처/국내 오퍼 확인 시각이 저장되어
상품 상세 화면에 표시됩니다. 분석할 때마다 새 행이 추가되어 점수 이력이 남고, 최신 행이 현재
값이며 검토 상태는 이어집니다.

## Phase 3 동작 방식

**어댑터 (공식 문서로 확인한 API만)**

| 소스 | 엔드포인트 | 용도 |
|---|---|---|
| eBay Browse API | `GET /buy/browse/v1/item_summary/search` (+OAuth client credentials) | 해외 공급가. `deliveryCountry:KR`·새상품·즉시구매 필터 |
| 라쿠텐 이치바 상품 검색 (2026-07-01) | `GET /ichibams/api/IchibaItem/Search/20260701` | 일본 공급가 (JPY) |

공식몰·리테일러 사이트 크롤링은 구현하지 않습니다 (이용 조건 미확인). 해당 가격은 `supplier_offers.csv`로 가져오세요.

**검색어 (PRD 9.2)** — 소스 언어별로 모델 번호(eBay는 GTIN 우선) → 브랜드+모델 → 브랜드+상품명 → 현지어 상품명 →
브랜드+카테고리 순. 현지어 이름은 `brand_aliases.yaml`의 `local_names`(사용자 확인값)에서만 가져오며 기계 번역하지 않습니다.
구체적인 검색어에서 확실한 매칭이 나오면 이후 단계는 호출하지 않습니다.

**리스팅 매칭 (PRD 9.3)**

| 근거 | 상태 | 가격 비교 |
|---|---|---|
| 모델번호(또는 GTIN 검색) + 브랜드, 위험어 없음 | 자동 매칭(미검증) | 반영, `공급처 미검증` 표시 |
| 숫자 모델번호만 일치 / 액세서리·중고·묶음 의심 | 검토 필요 | 제외 |
| 브랜드 + 상품명·별칭 (모델번호 없음) | 검토 필요 | 제외 |
| 그 외 | 저장 안 함 | — |

상품 상세에서 오퍼를 **확정/제외**하면 같은 리스팅의 모든 관측에 적용되고, 다시 검색해도 유지됩니다.
가격이 바뀌면 새 관측 행이 생기고(이력 보존), 같으면 확인 시각만 갱신됩니다.

**공급처 신뢰도 (PRD 9.4)** — 공급처 유형 기본점수 + 판매자 평가 + 한국 배송 여부 + 배송비·재고 확인 여부 +
사용자 지정 신뢰 수준(신뢰/보통/차단). 품절·중고·차단·신뢰도 40점 미만 오퍼는 가격 비교에서 빠지며,
**최저가는 적격 오퍼 중에서만** 고릅니다. 반품 정책·구매 제한·정품/IP 메모는 '해외 공급처' 화면에서 관리합니다.
가격 반영 가능한 오퍼가 없어지면 이전 점수를 그대로 두지 않고 '평가 불가' 행을 기록합니다.

- 동일 입력 재실행 시 중복 저장 없음 + 점수 이력 보존
- 네이버 요청 형식, 그룹 수 제한, 재시도, 401/403 즉시 중단(비밀키 노출 없음), 호출 상한,
  키 미설정/소스 비활성/분야 코드 미설정 시 건너뜀, 수집 실패가 기존 데이터에 영향 없음
- 단계별·다국어 검색어, 리스팅 매칭(액세서리·중고·묶음·숫자 모델번호), 옵션 불일치 시 신뢰도 하향
- 공급처 신뢰도·제외 규칙, 더 싼 검토 필요/제외/차단 오퍼가 최저가로 선택되지 않음
- eBay 토큰 형식·캐시, GTIN/q 분리, 라쿠텐 404=결과 없음, 인증 오류 시 비밀값 미노출·즉시 중단, 호출 상한
- 재탐색 시 가격 이력 보존 + 사용자 결정 유지, 다른 통화 배송비 환산
- 면세 기준·관부가세·배송대행비 추정, 해외결제분에만 카드 수수료, 채널별 수수료, 목표 마진 판매가, 판정·정렬(적자 후순위),
  규제·배송기간 플래그, 미검증 오퍼 신뢰도 상한, 내 판매가 반영
- 모든 화면 렌더링, 영문 상태값 미노출, 목록→상세 이동, 채널 변경 시 재계산, 작업 결과 유지, 빈 화면 안내,
  미검증 후보가 '검증 완료'로 표시되지 않음, UI에서 연결 확정

## 원가·판정 방식

**원가 (전부 원화, `config/scoring_config.yaml`에서 조정)**

| 항목 | 기본 가정 | 기준 |
|---|---|---|
| 상품가 + 판매처 배송비 | 오퍼 값 | 해외 결제액 |
| 해외 카드 수수료 | 2.5% | 해외 결제액 |
| 환율 여유분 | 3% | 해외 결제액 |
| 국제배송(배송대행) | max(무게, 1kg) × 국가별 요율 (US 12,000 / JP 8,000 / EU·GB 15,000원/kg) | 무게 미입력 시 카테고리 기본 무게 |
| 관부가세 | 해외 결제액이 면세 기준(미국 US$200, 그 외 US$150) 이하면 0, 초과 시 관세 8% + 부가세 10% | 추정치 |
| 포장·기타 | 1,000원 | |
| 판매 수수료 | 스마트스토어 6% / 쿠팡 11% / 기타 10% | 판매가 |
| 반품·CS 충당 | 3% | 판매가 |

면세 기준·세율은 일반적으로 알려진 값을 넣은 **추정치**이며 품목·제도에 따라 다릅니다. 실제 통관 판단을 대체하지 않습니다.

**판매가** — `my_sale_price_krw`(상품 상세의 '판매 조건'에서도 입력 가능)가 있으면 그 값, 없으면 국내 시장 최저가.
**목표 마진 판매가** = 판매 수수료 전 원가 ÷ (1 − 판매 수수료 − 반품 충당 − 목표 마진)을 함께 계산해 시장 최저가와 비교합니다.

**판정 (정렬 1순위)**

| 판정 | 조건 |
|---|---|
| ✅ 소싱 검토 | 목표 마진 이상, 목표 마진 판매가 ≤ 시장 최저가 |
| ⚠️ 조건부 | 이익은 나지만 목표 마진 미달이거나, 목표 마진을 맞추려면 시장가보다 비싸게 팔아야 함 |
| ⛔ 제외 권고 | 예상 적자 또는 평가 불가 |

후보 목록은 판정 → 종합점수 순으로 정렬되므로 수요가 높은 적자 상품이 위로 오지 않습니다.
수입·배송 규제(`import_rules.yaml`)와 배송 기간(14일 초과)은 위험 요소로 표시됩니다.
미검증 오퍼로 계산한 후보의 데이터 신뢰도는 '미검증'을 넘지 않습니다.

## 점수 산정 (초기 가설)

`total = 수요×0.30 + 성장×0.20 + 가격×0.20 + 마진×0.20 + 경쟁×0.10` (각 0~100).
종합점수는 같은 판정 안에서의 순위 참고용입니다. 가중치·정규화 기준은 `config/scoring_config.yaml`에서 조정합니다. 상품은 승인 상태이면서 위험 요소가 하나도 없을 때만 '검증 완료'로 표시됩니다.

## 알려진 제한 사항

- **샘플 데이터는 가상**입니다. `data/sample`의 가격·수요 수치는 개발용이며 실제 시장 정보가 아닙니다.
- **네이버 검색어 트렌드는 실제 호출로 확인**했습니다(API HUB, HTTP 200). 쇼핑 인사이트와 eBay·라쿠텐 실제 호출은 검증하지 못했습니다. 요청/응답 처리는 공식
  문서(eBay는 OpenAPI 명세) 형식을 기준으로 가짜 transport로 테스트했습니다. 키 설정 후 처음 실행할 때 데이터 소스
  관리 화면에서 결과를 확인하세요.
- **수요 지수는 상대 지수**입니다. 검색량·클릭량의 상대 비율이며 판매량이 아닙니다. 기준 키워드
  스케일링은 같은 기준 키워드를 쓰는 동안에만 비교 가능합니다.
- **쇼핑인사이트는 분야 코드 필요**: 코드를 확인해 직접 입력해야 하며, 기본값은 비어 있습니다.
- **국제배송비·관부가세는 추정치**입니다 (무게 × 요율, 면세 기준·기본 세율). 배송대행지 실제 견적과 품목별
  HS 세율로 `scoring_config.yaml`을 고쳐 쓰세요. 수입 규제 경고는 키워드 기반 알림일 뿐 법적 판단이 아닙니다.
- **환율은 CSV 수동 입력**입니다. 미지원 통화 상품은 임의 환율로 계산하지 않고 건너뜁니다.
- Google Trends·공공 통계(관세청 등) 어댑터는 아직 없습니다. 이용 조건·인증이 확인된 경우에만
  추가합니다. 그 전까지는 해당 데이터를 `demand_signals.csv`로 가져올 수 있습니다.
- **해외 가격 ≠ 최종 원가**: eBay 검색 결과에는 재고 수량이 없고, 라쿠텐이 배송비 별도(`postageFlag=1`)이면
  배송비를 알 수 없어 0으로 계산하고 `해외 배송비 미확인`으로 표시합니다. 라쿠텐 평점은 상품 리뷰 평균입니다.
- **국내가 자동 수집은 없습니다.** 네이버 쇼핑 검색 API가 2026-07-31 종료되어(대체 API 없음) `domestic_offers.csv`로만 입력합니다.
- 모델 번호가 없는 상품은 자동 매칭되지 않고 모두 검토 필요로 분류됩니다.
- 크롤링, CAPTCHA·로그인 우회는 구현하지 않습니다.
